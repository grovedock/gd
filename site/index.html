How a change lands

  1. An agent sends the files it changed.Over the CLI, plain git push, an SDK or MCP. No clone of history needed.
  2. The server checks only those paths.If the branch moved but nothing touched your paths, the server rebases for you. If something did, you get the reason and the paths.
  3. The branch moves once per batch.Every queued change lands with one compare-and-swap. A conflicting change fails alone; the rest land.

Keep your current host, or leave it

  • Mirrorgd mirror pushes every landed change to GitHub, GitLab or Bitbucket, so CI and everything else keep working. Stop it to roll back. Mirroring
  • Migrategd migrate brings history, open pull requests and issues over in one command, and gd export-git takes the history back any time. Migrating

For agents: a URL and a token

Agents read, search, write and land files over the Model Context Protocol without cloning anything. Each token is limited to its repositories, a role and an expiry, and every action is in the audit log.
